# 小红书数据源选型与 TikHub 验收

## 当前路线

TikHub App V2 原为公开评论的首选。**2026-11-22 起，顶层评论首选改为 browser-native 的 `xiaohongshu-mcp`**（见 [xiaohongshu-mcp.md](xiaohongshu-mcp.md)）：`scripts/xhs-mcp detail` 一次调用就返回笔记正文、互动数据和**第一页评论**，免费且不需要签名。TikHub 保留为**按需路线**——只有在需要二级回复（`get_note_sub_comments`）、跨页续读或折叠评论覆盖时才启用，因为它要消耗额度。搜索和笔记正文同样优先走 `scripts/xhs-mcp`，`xhs` CLI 为备选。执行入口和凭据配置见 [social.md](social.md#comments-via-tikhub-app-v2)。

2026-11-22，TikHub [官方价格接口](https://docs.tikhub.io/186826054e0)显示两个评论端点各 $0.01/次，均接受免费额度。App V2 [关键词搜索](https://docs.tikhub.io/420136398e0)也是 $0.01/次，但不接受免费额度。历史社区报价不作为计费依据。上线前核对实际端点价格和额度；HTTP 200 也可能带有上游错误并产生收费。

## 本机实测（2026-11-22）

| 项目 | 结果 | TikHub 请求 ID |
| --- | --- | --- |
| 用户提供的公开笔记 `6b0230d10000000009020aa9` | 10 条非空顶层评论，`has_more=false` | `bb1c9c10-344a-4ab1-8190-46a4fa7607e3` |
| 同一笔记的单个评论线程 | 2 条非空回复，`has_more=false` | `8ad71d2e-5e03-4096-b8fe-d283efb82283` |
| 官方文档的笔记样本 `697c0eee000000000a03c308` | 首两页分别为 10、15 条非空评论，ID 无重叠；第二页仍有后续 | `864400e4-4000-4d94-910c-c20385bac29a`、`b8d75bbb-367f-447a-997e-3ee72a751a74` |

四次内容请求共用 $0.04 免费额度，付费余额维持 $0。顶层续页实测将完整游标字符串连同其中的 `index`、`pageArea` 交回接口。二级实测只覆盖首页，折叠评论覆盖也未验证。以上是 API 实测；本地脚本的离线回归与新增账户的使用额度分别核验。

## 选型依据和备用候选

以下为用户于 2026-11-21 提供的社区调研结论。带有候选标识的路径不参与自动回退，也没有本机实测证据。

| 路线 | 判断 |
| --- | --- |
| TikHub | 两轮共四个独立帖提名。2026-01 有接入后 token 无效、返回 0 条笔记的案例；开始批量任务前先验证授权、评论正文和余额。[推荐讨论](https://linux.do/t/topic/3116169) · [失败反馈](https://linux.do/t/topic/1407486) |
| 知乎数据开放平台 | 免费搜索候选。反馈称额度低、入口难找，只看到搜笔记线索，评论能力待验证。[来源](https://linux.do/t/topic/3186113) |
| xpzouying/xiaohongshu-mcp | **已评估并上线，现为 browser-native 主路由**（2026-11-22）。自部署，REST + MCP，Apache-2.0。核对 `/api/v1/feeds/detail` 的结论成立：该端点一次返回正文、作者、互动数据、第一页评论和视频笔记的签名字幕直链，本机实测 14 条真实评论、字幕 HTTP 200。发评论演示仍不能当作读评论证据，且上游发布路由当前因 issue #919/#921 不可用。本机部署与验收见 [xiaohongshu-mcp.md](xiaohongshu-mcp.md) |
| MediaCrawler | 降级候选。调研报告记录了挂掉、二级评论 406 和非商用限制；维护活跃度不等于当前路线稳定。[使用反馈](https://linux.do/t/topic/781290) |
| 「蒲公英」 | 待查，只有一次提名，缺少价格和评论能力证据。[来源](https://linux.do/t/topic/3116169) |
